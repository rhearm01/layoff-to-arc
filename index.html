Concept for the Product Engineer role · sample data

Laid off? Here's your first week.

The layoffs tracker meets people on a hard day, then offers a generic "Browse open roles" link. This turns each row into a 7-day plan, roles matched to the person, and warm intros, with the signup asked for last. Everything below is clickable.

    06

    How I would measure it

    Primary metric: accepted intros per 100 tracker visitors. Downstream: interviews scheduled and hires, reported back by founders. Guardrails: unsubscribes, intro decline rate, candidate and founder satisfaction.

    A/B test: half of tracker visitors see today's row link, half see "I was affected". Same page and traffic. Ship only if accepted intros rise without worse guardrails.

    07

    How I would ship it

    1. An "I was affected" button on each tracker row opens a drawer. No signup to see the plan.
    2. Matching calls the public jobs API (or the MCP search_jobs tool) with function, seniority, location and remote. A sponsorship filter only if the data supports it.
    3. Anonymous visitors keep progress locally in the browser. It syncs to Postgres after signup, using their existing infrastructure where possible. Events go to GA4 or whatever analytics they already use.
    4. join_network runs only after an explicit yes, as their docs require.
    5. Week one: button, drawer, plan, matching, event logging and the A/B flag. Nothing else.
